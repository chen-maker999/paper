# Keep the Ledger, Drop the Logs：面向长程 LLM Agent 的状态键控上下文压缩

**研究方向：Agent 上下文压缩与状态保持（context compression & state retention）**

论文 PDF：[`paper/main.pdf`](paper/main.pdf)（英文，LaTeX 源码在 `paper/`）

## 一句话总结

Agent 的上下文不是“一段需要缩短的文本”，而是“一条不断改写状态的事件日志”。
压缩时真正不能丢的是**每个状态变量的最新值**。我们借用数据库的
**日志压实（log compaction）**思想，提出 *State-Keyed Compaction (SKC)*：
按状态键只保留最新写入（原文、带出处），再配一个短的近期窗口和旧动作骨架。

## 核心贡献

1. **形式化**：把 Agent 历史建模为带“键-值写入”的事件日志；用**理想读取器**把
   “压缩丢了什么”和“模型能不能读懂”分开；每个状态探针有三种结果：
   **正确 / 过期（stale）/ 缺失**。过期比缺失更危险——Agent 会自信地基于旧状态行动。
2. **理论**（附录有证明）：
   - 压实日志是充分统计量，大小只取决于活跃键数量，与轨迹长度无关，并达到
     `K·log|V|` 比特下界；
   - **替代一致（supersession-consistent）**的压缩器永远不会产生过期状态
     （近期窗口、压实日志都属于此类）；
   - 近期窗口按“年龄”而非“重要性”遗忘：保留概率 `1 − exp(−λW/μ)`；
   - 与替代关系无关的选择（BM25、随机、token 重要性）过期率为
     `(1−ρ)(1−(1−ρ)^{m−1})`；同一公式也刻画了召回率为 `r` 的抽取器喂给账本时的过期率；
   - 推论：只要账本里有最新值，剩余预算可以安全地用于相关性选择（SKC+BM25）。
3. **方法**：三层压实。键级是账本（每个状态只留最新值，原文保存并带出处）；内容级是替代感知的行级去重；效用级是学习型效用背包，带替代安全约束，效用模型直接从日志中免费学习。全程不调用 LLM。
4. **实证**：2 种 Agent 框架、12 组 LLM 配置，共 4,979 条公开轨迹，配合 bootstrap 置信区间；3 个 LLM 读取模型的在环实验；消融实验与神谕上界；可控合成基准 StateTrack。

主要数字见下方“结果摘要”。详细表格在 `results/final/`，复现方法见 `docs/`。

## 结果摘要

**数据**：公开的 SWE-bench 轨迹共 4,979 条，涵盖 2 种 Agent 框架（SWE-agent、OpenHands）、12 组 LLM 配置（含开源模型），全部按真实 BPE token 计数。

| 实验 | 结果 |
|---|---|
| 状态保持（Lite 测试集 1,429 条，4k / 8k / 16k / 32k 预算） | SKC 65.0 / 74.8 / 85.0 / 91.8%，最佳基线 57.8 / 67.3 / 75.7 / 82.5%，提升 +7.2~+9.4 分（p<0.001） |
| 跨框架泛化（OpenHands 等 1,050 条，模型未见过的框架和 LLM） | 提升 +3.4~+5.9 分（p<0.001），7 组配置全部领先 |
| 过期率 | SKC 0.1–0.3%，与近因窗口持平；选择类方法 1.0–2.8%，在被改写 3 次以上的键上达 9–13% |
| 压缩率 / 速度 | 4k 预算时压缩 4.7 倍；每步 0.1–0.25 秒，不调用 LLM |
| LLM 读取（3 个读取模型、2 个家族） | 状态问答正确率：SKC 77.0 / 50.2 / 59.9%，最佳基线 40.1 / 24.9 / 27.2%，LLM 摘要仅 2–7%；下一步动作预测与基线无显著差异 |
| 端到端（ALFWorld，134 局，预算 300–1200 token） | 各压缩方法之间无显著差异（p≥0.45）；压缩本身在 300/400 token 时比不压缩低 18/13 分，说明状态保持的优势没有转化为成功率提升 |
| 不足 | 下一步复制的代码行上，切块 BM25 领先 1–8 分；神谕效用实验表明框架上限可达 93–95% |

## 仓库结构

```
skc/                 核心库
  core.py            数据模型（Turn / Write / Unit）、证据匹配、理想读取器
  compressors.py     基线（窗口、观测遮蔽、截断、BM25、随机）与 SKC-basic
  utility.py         SKC（三层压实、效用模型特征）、BM25 切块、自信息剪枝基线
  sweagent.py        SWE-agent 轨迹解析（0.x 与 1.x 两代接口）→ 状态写入
  openhands.py       OpenHands 轨迹解析（消息、事件流、文本函数调用三种格式）
  synthetic.py       StateTrack 合成基准生成器、带噪抽取器
  evaluate.py        状态探针与“使用探针”评测
experiments/         下载数据、统计、主实验、消融、合成实验、作图
results/             所有实验输出（csv / markdown 表格）
paper/               论文 LaTeX 源码、图、PDF
tests/               单元测试（pytest）
run_all.sh           一键复现
```

## 复现

只需 CPU（4 核约 1 小时）：

```bash
pip install -r requirements.txt
python -m pytest -q
./run_all.sh            # 下载约 6GB 公开轨迹 → 解析 → 全部实验 → 作图 → 编译论文
```

轨迹来自 SWE-bench 官方公开的提交记录（`swe-bench-submissions` 公共 S3 桶，
即 github.com/SWE-bench/experiments 所引用的数据）。
